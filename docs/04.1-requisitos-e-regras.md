# 📋 4.1 Requisitos e regras da interface web

> **FONTE ÚNICA** Os requisitos de negócio da API (RF01–RF10), os RNF do backend e as regras RN01–RN09 estão em [studytube-backend/docs/04.1-requisitos-e-regras.md](https://github.com/danibenfica/studytube-backend/blob/main/docs/04.1-requisitos-e-regras.md). Aqui ficam só os requisitos **da tela**, com prefixo `W` (Web), ligados aos mesmos casos de uso.

## 4.1.1 Atores

| Ator | Tipo | Descrição |
|---|---|---|
| 🎓 Usuário (estudante) | Principal | Usa a página no navegador. |
| 🖥️ StudyTube API | Secundário (sistema) | Recebe e devolve as videoaulas (`/api/videos`). |
| ▶️ Player do YouTube (IFrame) | Secundário (sistema externo) | Reproduz o vídeo incorporado via `react-youtube`. |

## 4.1.2 Requisitos funcionais da interface (RFW)

| ID | Requisito | UC | Implementação | RF da API | Estado |
|---|---|---|---|---|---|
| RFW01 | A tela deve ter um campo para colar o link do YouTube e a opção "Adicionar ✨". | UC_001 | `VideoForm` | RF01 | ✅ |
| RFW02 | A tela deve validar no navegador se o link é do YouTube antes de chamar a API. | UC_007 | `isValidYouTubeUrl` | RF05 | ✅ |
| RFW03 | A tela deve listar as videoaulas com miniatura, título, canal e duração formatada, na ordem recebida da API (mais recentes primeiro). | UC_002 | `App`, `VideoCard`, `formatDuration` | RF02 | ✅ |
| RFW04 | A tela deve permitir marcar ("✔ Já assisti") e desmarcar ("↩ Desmarcar"), destacando o card assistido. | UC_003, UC_004 | `VideoCard`, `useVideos.toggleWatched` | RF03, RF04 | ✅ |
| RFW05 | A tela deve reproduzir a videoaula num player incorporado, com reprodução automática e opção "Fechar player ✖". | UC_005 | `VideoPlayer` (`react-youtube`) | — | ✅ |
| RFW06 | A tela deve mostrar o progresso "X de Y assistidos 🌸". | UC_006 | `WatchProgress`, `watchedCount` | — | ✅ |
| RFW07 | A tela deve mostrar mensagens de erro da API e avisar quando a API não responde na carga. | UC_001–UC_004 | `useVideos`, `videosApi.handleResponse` | RF05 | ✅ |
| RFW08 | A tela deve orientar o estudante quando a lista estiver vazia. | UC_002 | `App` | — | ✅ |
| RFW09 | Telas mobile em React Native consumindo a mesma API. | — | Repositório inexistente | RF08 | 🗺️ |
| RFW10 | Telas de playlists. | — | Não existe | RF06 | 🗺️ |

## 4.1.3 Requisitos não funcionais da interface (RNFW)

| ID | Característica (ISO/IEC 25010) | Requisito | Como aparece no código |
|---|---|---|---|
| RNFW01 | Manutenibilidade — modificabilidade | O endereço da API deve ser configurável. | `VITE_API_URL` (padrão `http://localhost:5126/api/videos`), `.env.example`. |
| RNFW02 | Manutenibilidade — testabilidade | Utilitários e componentes devem ter testes automatizados. | Vitest 5 + Testing Library + jsdom: 18 testes. |
| RNFW03 | Manutenibilidade — analisabilidade | Código verificado por lint e tipagem antes do commit e no CI. | ESLint 10, TypeScript (`tsc -b` no build), Husky `pre-commit`. |
| RNFW04 | Portabilidade | Rodar em Windows, macOS e Linux. | CI em `ubuntu-latest` e `windows-latest`; Node em `.nvmrc` (24); `engines.node`: `^22.13.0 \|\| ^24.0.0 \|\| >=26.0.0`. |
| RNFW05 | Segurança — confidencialidade | O navegador não deve conhecer a chave da YouTube Data API. | Metadados vêm da API; o frontend só usa o player público. |
| RNFW06 | Compatibilidade — interoperabilidade | Tipos do frontend devem seguir o `VideoDto`. | `types/Video.ts`. |
| RNFW07 | Usabilidade — proteção contra erro | Não permitir enviar campo vazio e avisar link inválido antes de chamar a API. | Botão desabilitado com campo vazio; alerta de link inválido. |

## 4.1.4 Regras da interface (RNW)

| ID | Regra | Onde | Mensagem / efeito |
|---|---|---|---|
| RNW01 | O link, sem espaços nas pontas, deve começar com `http://` ou `https://` (opcional), `www.` (opcional) e `youtube.com/` ou `youtu.be/`. | `isValidYouTubeUrl` | Alerta "Esse link não é do YouTube 🥺". |
| RNW02 | A opção "Adicionar ✨" fica indisponível enquanto o campo está vazio. | `VideoForm` | Botão desabilitado. |
| RNW03 | Videoaula adicionada entra no **topo** da lista sem recarregar a página; o campo é limpo só quando dá certo. | `useVideos.add`, `VideoForm` | — |
| RNW04 | Mensagem de erro da API é mostrada exatamente como veio em `error`; sem esse campo, a tela mostra "Algo deu errado 😢". | `videosApi.handleResponse` | Texto em vermelho abaixo do formulário. |
| RNW05 | Se a lista não carregar, a tela mostra "Não consegui falar com a API. Ela está rodando? 🥺". | `useVideos` | — |
| RNW06 | A mensagem anterior é apagada a cada nova tentativa de adicionar, marcar ou desmarcar. | `useVideos` | — |
| RNW07 | O indicador de progresso só aparece quando há pelo menos uma videoaula; a mensagem de lista vazia só aparece quando não há erro. | `WatchProgress`, `App` | "Nenhum vídeo ainda... cole seu link aqui! 🐰" |
| RNW08 | A duração aparece como `m:ss` ou `h:mm:ss` (dias somados às horas; frações de segundo ignoradas). | `formatDuration` | Ex.: `00:04:13` → `4:13`; `1.02:03:04` → `26:03:04`. |
| RNW09 | Assistir não marca a videoaula como assistida; só um vídeo fica no player por vez. | `App`, `VideoPlayer` | — |

As regras de negócio da API (RN01–RN09) continuam valendo: por exemplo, um link aceito pela RNW01 ainda pode ser recusado pela API (ver [Anexo E, NC-F03](anexo-e-registro-de-revisao.md)).
